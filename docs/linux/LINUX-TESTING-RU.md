# Vortex Linux — пошаговая проверка (п. проверки по-русски)

Сценарии английской версии: `TESTING.md`. Здесь — тот же набор по-русски,
с командами и критериями успеха, плюс шаблон протокола для записи
результатов. «Недостающая часть» отчёта: проверка на реальном Linux-хосте.

## 0. Что взять

Дистрибутив Linux x86_64 (Ubuntu/Debian 22.04+ рабочие). Файлы из прогона
34167843426:

- `Vortex-1.0.0-linux.7.zip` (251 МБ) — распаковать:
  ```sh
  unzip Vortex-1.0.0-linux.7.zip -d ~/vortex-linux
  cd ~/vortex-linux
  ```
- RPM можно ставить напрямую (`sudo dnf/rpm -i`) либо просто распаковать из zip.

Зависимости рантайма (типично для Electron/Chromium):
```sh
sudo apt-get install -y libnss3 libnspr4 libatk1.0-0 libatk-bridge2.0-0 \
  libcups2 libdrm2 libxkbcommon0 libxcomposite1 libxdamage1 libxrandr2 \
  libgbm1 libasound2 libpango-1.0-0 libcairo2 libpixman-1-0 xdg-utils
```

## 1. Запуск (первый smoke)

Сразу после расжатия `chrome-sandbox` может не иметь setuid — обычная ситуация
для распакованных tarball. Правильно:

```sh
sudo chown root:root chrome-sandbox && sudo chmod 4755 chrome-sandbox
./vortex
```

Для быстрого smoke без прав (не для боевой вкладки):
```sh
./vortex --no-sandbox
```

Критерий успеха:
- [ ] появилось окно Vortex;
- [ ] в консоли/журнале нет падений (см. `~/.vortex/logs/vortex.log`);
- [ ] старт с `--no-sandbox` не понадобился после корректной установки
      `chrome-sandbox` (проверка безопасности песочницы).

## 2. Верификация native-модулей (runtime)

Запустить с флагом удалённой отладки (для диагностики):
```sh
./vortex --remote-debugging-port=9222
```
Через DevTools-протокол (или в DevTools-консоли) вызывать:
```js
require('winapi-bindings');                  // должен загрузиться как ELF-аддон
const fid = require('@nexusmods/fomod-installer-native'); // native fomod
const leveldown = require('leveldown');      // instance level
```
Критерий:
- [ ] каждый `.node` из списка `app.asar.unpacked` загружается без
      `NODE_MODULE_VERSION`-ошибок и вызова неправильной сборки;
- [ ] `winapi-bindings` (старый EEXIST-пациент) отвечает на вызовы пустым
      результатом без краша;
- [ ] `require('loot')` даёт ожидаемый `MODULE_NOT_FOUND` (N-03, LOOT не порт).

## 3. FOMOD-мастер

- [ ] установка мода с `*_fomod`-пакетом открывает мастер, выбор опций
      работает (условия XML, опционные узлы);
- [ ] отмена в середине мастера не ломает очередь (just: unlink-очередь
      стабильна — покрыто юнит-тестом 0003);
- [ ] «недоверенные» записи архива (path traversal) блокируются.

## 4. Деплой на реальную игру

- Путь к игре назначить вручную (non-Steam EXE):
  - Windows-EXE + префикс Wine/Proton: проверяется, что
    `detectProtonUsage` находит `compatdata/<id>/pfx/drive_c`, префикс
    подхватывается;
- [ ] мод с папкой `Data` деплоится в существующую `data` (чувствительность
      к регистру — разрешена на уровне целевой игры), конфликт `Data`+`data`
      явно выведен, а не выбран молча (юнит-покрытие 0005/0007);
- [ ] disable/purge/restore оставляют дерево чётким (external-change
      регистрируется и сравнивается по контенту).

## 5. BSA/BA2-архивы

- [ ] BSA/BA2-мод устанавливается, извлечение идёт в переносимое место
      (конфигурация `gamebryo-archive-support` без виндовых путей);
- [ ] в деплое используются извлечённые файлы, а не «бинарник прямо из архива».

## 6. nxm:// хендлер

- [ ] холодный старт: клик по `nxm://...` после выхода из Vortex поднимает
      приложение и передаёт URL целиком (ссылка с пробелами/спецсимволами);
- [ ] тёплый старт: ссылка при работающем Vortex попадает в окно;
- [ ] `xdg-mime query default x-scheme-handler/nxm` показывает установленный
      обработчик (после регистрации в десктопном режиме).

## 7. Инструменты и runner

- [ ] внешний инструмент (напр. FNVEdit, .exe) с ручным выбором
      runner/префикса запускается; владелец пути — граница компонентов
      (`/Games/Foo` не «родитель» для `/Games/FooBar` — юнит-покрытие 0005);
- [ ] Steam-игра запускается через `-applaunch <id>` с найденного
      библиотечного пути (покрытие 0002/0004).

## 8. Протокол результатов

Заполнить и приложить к отчёту: дата, дистрибутив (`cat /etc/os-release`),
графика/драйвер, вывод `./vortex --version` (или первая строка лога),
список unzip-файлов с размерами, `sha256sum` артефакта сверяется со
`SHA256SUMS` из релиза. Каждый чекбокс — «да/нет/почему», плюс копия логов
`~/.vortex/logs/` и user-data `~/.vortex/` при проблемах.

Известные ожидаемые «нет» (не являются багами):
- LOOT-сортировка (N-03 — модуль не портирован);
- автоматический импорт GOG/Heroic/Faugus/Bottles (R-03) — только ручной
  attach;
- Flatpak (F-01) — отдельно, после переносимой сборки.
