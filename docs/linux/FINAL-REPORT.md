# Linux-порт Vortex — итоговый отчёт (Linux native readiness)

Статус: работа выполнена в ночной сессии 2026-09-07→08 по схеме
«портировать задачу из форка честно + воспроизводимый CI + первый
Linux-артефакт». Отчёт честный: зелёное — только то, что реально
проверено; всё остальное перечислено как непроверенное.

## Что сделано

- Ветка `linux/native-readiness-20260908-0017` в `vertigo-red/Vortex` создана
  ровно на актуальном upstream `master` (base
  `9c641bd78f7f551df3645a0f5b2bf08fe656e78f`, Nexus-Mods/Vortex, свежий fetch).
  В ветку не вливалось ничего из `master` форка; все изменения — cherry-pick
  порта + собственные фиксы CI.
- Перенесено 7 коммитов порта (исходники + тесты, атрибуция `-x`):
  - Steam: поиск библиотек + запуск по найдённому app ID (0002),
  - стабильные unlink-очереди при залоченных файлах (0003),
  - Proton: `pfx/drive_c`, числовая сортировка версий, глобальный дефолт,
    поиск по всем библиотекам, без безусловного `LD_PRELOAD` (0004),
  - резолвер регистронезависимых путей + границы компонентов пути для
    инструментов/деплоя (0005, 0007),
  - переносимый `nxm://`-обработчик + `rpm`-таргет (0006),
  - BSA/BA2-архивы с переносимыми путями извлечения (0009).
- Собственные фиксы поверх порта:
  - `B-01` ОС-специфичные `extraResources`: Windows-redistributables ушли в
    `win.extraResources`, Linux несёт только `locales` (в payload проверено:
    55 локальных паков).
  - `B-03` `EEXIST` при упаковке: `USE_HARD_LINKS: "false"` для electron-builder
    (winapi.node теперь в payload).
  - `B-05` `homepage` в `src/main/package.json` — обязателен rpm-таргетом.
  - Гейт native-модулей в deploy-tree: 7 обязательных модулей — жёстко,
    `loot` — предупреждение (см. N-03).
- Рабочий процесс `.github/workflows/linux-readiness.yml`: verify всегда,
  тяжёлая упаковка — по коммиченному маркеру (теперь удалён) или вручную
  (`workflow_dispatch`). Никаких секретов (`contents: read`), подписей,
  релизов, upstream-refs.

## Что НЕ проверено (требует Linux-хоста и реальных установок)

Julia — только запуск на реальном Linux может подтвердить:

- старт приложения и окно;
- обнаружение и запуск игр (Steam/Proton, вручную назначенные EXE);
- FOMOD-мастер установки, BSA/BA2-установку реального мода;
- холодный и тёплый `nxm://`-запуск на десктопе;
- вызов внешних инструментов;
- деплой на реальную игру (регистронезависимость на живой ФС);
- загрузку native-модулей внутри упакованного Electron (проверено только
  наличие файлов).

## Известно НЕ работает / отложено

- **N-03 LOOT: не работает на Linux вообще** (сортировка по LOOT недоступна).
  `node-loot@6.2.3` в `loot_api/` несёт только Windows-бинарники; Linux-prebuilt
  нет, fallback-сборка линкует отсутствующий `loot_api/libloot`. Это отдельная
  работа по порту (линковка системного `libloot-dev`, либо вендорный
  Linux-`libloot`). В упакованном виде модуль отсутствует, гейт сообщает WARN.
  Форк также не портировал LOOT на Linux (в его отчёте это «remaining product
  work»).
- **R-03** неавтоматическое обнаружение GOG/Heroic/Faugus/Bottles: не
  портировано в этой сессии (ручной attach путей — возможен, но не протестирован).
- **R-04** игроспецифичные пути (DA:Origins/Bethesda за префиксом) — частично,
  требует реальных установок.
- **F-01 Flatpak**: upstream-документированная сломанная сборка (pnpm);
  сознательно отложено — сначала переносимая сборка.
- **R-06** возможности хардлинков на разных ФС (EXDEV, Btrfs/подтома) — не
  проверялось вне юнит-тестов.
